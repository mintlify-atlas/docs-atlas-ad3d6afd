Weiroll is a flexible execution system for trust-minimized and gas-efficient scripting on Ethereum. The DeployableVM contract provides a simple way to integrate Weiroll's powerful scripting capabilities into your smart contracts via delegatecall.

## Installation

<Steps>
  <Step title="Install Weiroll using Foundry">
    Add Weiroll to your Foundry project:

    ```bash
    forge install cowprotocol/weiroll
    ```

    <Note>
      Make sure you have Foundry installed. If not, visit [getfoundry.sh](https://getfoundry.sh) to install it.
    </Note>
  </Step>

  <Step title="Update your foundry.toml">
    Add the Weiroll library to your `foundry.toml`:

    ```toml
    [profile.default]
    src = "src"
    out = "out"
    libs = ["lib"]
    
    # Recommended compiler settings
    via_ir = true
    optimizer = true
    optimizer_runs = 1000000
    solc = "0.8.27"
    ```
  </Step>
</Steps>

## Basic Usage

The DeployableVM is designed to be called exclusively via `delegatecall` from your contract. This ensures that the Weiroll VM executes in your contract's context with access to your contract's storage and state.

### Import the Contract

```solidity
import {DeployableVM} from "weiroll/src/DeployableVM.sol";
```

### Execute Scripts via Delegatecall

Here's a complete example showing how to integrate DeployableVM into your contract:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import {DeployableVM} from "weiroll/src/DeployableVM.sol";

contract MyContract {
    DeployableVM public immutable weirollVM;
    
    constructor(address _weirollVM) {
        weirollVM = DeployableVM(_weirollVM);
    }
    
    function executeScript(
        bytes32[] calldata commands,
        bytes[] memory state
    ) external payable returns (bytes[] memory) {
        // Execute the Weiroll script via delegatecall
        (bool success, bytes memory result) = address(weirollVM).delegatecall(
            abi.encodeCall(DeployableVM.execute, (commands, state))
        );
        
        require(success, "Weiroll execution failed");
        
        return abi.decode(result, (bytes[]));
    }
}
```

<Warning>
  The `execute` function will revert with `CallableOnlyViaDelegateCall()` if called directly. It must always be called via `delegatecall`.
</Warning>

## Deployment

To deploy the DeployableVM contract with a deterministic address:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import {DeployableVM} from "weiroll/src/DeployableVM.sol";
import {Script} from "forge-std/Script.sol";

contract DeployableVMScript is Script {
    function run() public {
        vm.startBroadcast();

        // Deploy with deterministic salt for cross-chain consistency
        DeployableVM weiVm = new DeployableVM{salt: ""}();

        vm.stopBroadcast();
    }
}
```

Deploy using Foundry:

```bash
forge script script/DeployableVM.s.sol:DeployableVMScript \
  --rpc-url $ETH_RPC_URL \
  --private-key $PRIVATE_KEY \
  --broadcast
```

<Tip>
  Using a deterministic salt (empty string or fixed bytes32) ensures the contract deploys to the same address across different chains, making your integration more portable.
</Tip>

## Troubleshooting

### CallableOnlyViaDelegateCall Error

If you encounter this error, ensure you're calling the `execute` function via `delegatecall`:

```solidity
// ✅ Correct
(bool success,) = address(weirollVM).delegatecall(
    abi.encodeCall(DeployableVM.execute, (commands, state))
);

// ❌ Wrong - will revert
weirollVM.execute(commands, state);
```

### Deployment Address Mismatch

If deploying on older Foundry versions, you may need to use a specific toolchain version:

```bash
foundryup -C cb9dfae298fe0b5a5cdef2536955f50b8c7f0bf5
```

This ensures deterministic deployment addresses match across environments.
